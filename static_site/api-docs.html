Introduction

The Protiddhoni Voice API lets you integrate voice campaigns, Dynamic TTS calls, contact management, wallet balance and call reporting (CDR) directly into your own application. It is a REST API that accepts and returns JSON over HTTPS, and is designed for server-to-server integration.

This documentation reflects the endpoints currently exposed to customers through the Protiddhoni portal. Where the current customer API reference does not specify a request field, response field, validation rule, status code or behavior, this page marks it explicitly rather than guessing — always confirm the exact schema against your portal API reference.

Base URL

https://portal.protiddhoni-bd.com/api

All endpoints are versioned under /v1. For example, the campaigns endpoint is:

https://portal.protiddhoni-bd.com/api/v1/campaigns

All requests must be made over HTTPS.

Authentication

Every request must include your API key in the X-API-Key request header. API keys are generated from the customer portal.

Required header

HeaderRequiredDescription
X-API-KeyYesYour account API key, generated in the customer portal.
Content-TypePOSTSet to application/json when sending a JSON request body.
 
X-API-Key: YOUR_API_KEY
Note: Bearer / Authorization token authentication is not used by the current API. Authentication is via the X-API-Key header only.

API Key Security

  • Generate your API key from the customer portal and treat it like a password.
  • Never expose your API key in frontend or browser code (HTML, JavaScript, mobile apps).
  • Use the API only from your backend — server-to-server requests.
  • Store the key in environment variables or a secrets manager, not in source control.
  • Rotate the key immediately if you suspect it has been exposed.
⚠ Never share real API keys. All examples on this page use the placeholder YOUR_API_KEY.

IP Whitelist

Where your portal account supports it, restrict API access to the known server IP addresses that will call the API. This limits the impact of a leaked key.

Not specified in the current customer API reference: whether IP whitelisting is enabled by default, and how it is configured. Check your portal settings or contact support to confirm availability.

Quick Start

The simplest request is checking your wallet balance — it needs only your API key and no request body:

curl https://portal.protiddhoni-bd.com/api/v1/wallet/balance \
  -H "X-API-Key: YOUR_API_KEY"

To send data (for example, creating a campaign), use POST with a JSON body and the Content-Type: application/json header:

curl -X POST https://portal.protiddhoni-bd.com/api/v1/campaigns \
  -H "X-API-Key: YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{ ... }'   # request body: see your portal API reference
Not specified in the current customer API reference: the exact request body fields for creating a campaign. Do not assume field names — use the schema shown in your portal API reference.

HTTP Responses

The API is a REST/JSON service, so it follows standard HTTP conventions: 2xx indicates success, 4xx indicates a client-side problem (such as authentication or input errors), and 5xx indicates a server-side error.

Not specified in the current customer API reference: the exact HTTP status code and JSON body returned by each endpoint. Your integration should read the actual HTTP status code and response body it receives, rather than relying on assumed codes.

Error Handling

Handle the following error situations in your integration. Detect them from the HTTP status code and the response body your request receives:

SituationHow to handle
Missing API keyNo X-API-Key header was sent — add the header.
Invalid API keyThe key is wrong, revoked, or for another account — check / rotate the key in the portal.
Validation errorThe request body or parameters were rejected — correct the payload per your portal API reference.
Insufficient balanceThe wallet balance is too low to run the requested calls — top up in the portal.
Invalid campaign / contact / callThe referenced resource (e.g. {id}) does not exist or is not on your account.
Rate limitingToo many requests in a short period — back off and retry.
Server errorA temporary error on the server — retry with backoff.
Not specified in the current customer API reference: the exact status codes, error codes, and JSON error structure for each of the above. Do not hard-code assumed codes or messages — branch on the real HTTP status and inspect the response body.

Integration Best Practices

  • Call the API server-to-server — never from browser or mobile client code.
  • Use HTTPS for every request.
  • Store your API key in environment variables or a secrets manager, never in source control or frontend code.
  • Rotate your API key immediately if it may have been exposed.
  • Use IP whitelisting where your portal account supports it.
  • Read the actual HTTP status code and response body — do not assume undocumented fields, codes or limits.
  • For list and CDR endpoints, follow the pagination scheme documented in your portal API reference.
  • Check wallet balance before large call runs.
