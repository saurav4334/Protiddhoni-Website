Overview

The Protiddhoni API powers voice automation across Bangladesh — Voice OTP delivery, multi-number broadcasts, and DTMF-driven surveys. All requests are made over HTTPS to api.protiddhoni.com/api, authenticated via a Bearer token, and respond with JSON.

This reference covers all endpoints in v1.0. Every write request takes a request_id — pass a unique 16–64 character string per call to prevent duplicate processing on retry.

Authentication

All API requests require a Bearer token in the Authorization header. You can obtain your API token from your dashboard → Account settings.

⚠ Important: keep your API token secure and never share it publicly. Treat it like a password — rotate immediately if leaked.

Required headers

HeaderDescription
AuthorizationBearer token for authentication
AcceptMust be set to application/json
Content-TypeRequired for POST requests — application/json

Example request headers

Authorization: Bearer your_api_token_here
Accept: application/json
Content-Type: application/json

Check balance

GET /api/balance Retrieve current account balance.

Returns the live balance for the authenticated account. Useful for pre-flight checks before bulk broadcasts so you don't get hit with a 402.

Response — 200 OK

{
  "success": true,
  "balance": 1250.75
}

Voice OTP broadcast

POST /api/broadcasts/otp Send a Voice OTP to one phone number.

Single-recipient OTP delivery. The voice you specify must be approved and have digit-mode enabled (so the OTP digits are spoken correctly). Use a unique request_id per call to make retries safe.

Body parameters

ParameterTypeRequiredDescription
request_idstringYesUnique request identifier (16–64 characters).
voicestringYesName of an approved voice with digit mode enabled.
senderstringYesAn active caller-sender number on your account.
phone_numberstringYesRecipient — 01XXXXXXXXX format.
otp_codestringYesThe OTP code to read out (4–6 digits).

Response — 200 OK

{
  "success": true,
  "broadcast": {
    "id": 123,
    "name": "otp_api_1_your_voice_019XXXXXXXX",
    "status": "broadcasting"
  }
}

💡 Note: use a unique request_id for each call to prevent duplicate processing on network retries.

Broadcast to multiple numbers

POST /api/broadcasts Send the same voice message to up to 999 numbers.

Bulk-send a voice message to multiple recipients in one request. Maximum 999 numbers per call — for larger campaigns, batch your requests.

Body parameters

ParameterTypeRequiredDescription
request_idstringYesUnique request identifier.
voicestringYesName of an approved voice.
senderstringYesActive caller-sender number.
phone_numbersarrayYesArray of phone numbers — max 999.

Response — 200 OK

{
  "success": true,
  "broadcast": {
    "id": 123,
    "name": "api_1_your_voice_3",
    "status": "broadcasting"
  }
}

List broadcasts

GET /api/broadcasts List all broadcasts in a date range.

Returns broadcasts on your account. Date range cannot exceed 90 days — for older history, paginate or query a smaller window.

Response — 200 OK

Get broadcast result

GET /api/broadcasts/:id/result Per-recipient delivery and answer status.

Once a broadcast finishes, this endpoint returns per-number outcome — answered, not-answered, failed — plus call duration in seconds for the answered ones.

Response — Completed

{
  "success": true,
  "isComplete": true,
  "statusDistribution": {
    "answered": 2,
    "notAnswered": 1,
    "failed": 0
  },
  "results": [
    {
      "phoneNumber": "019XXXXXXXX",
      "status": "answered",
      "duration": 45
    }
  ]
}

Create survey

POST /api/surveys Launch a survey campaign from a published template.

Surveys are built from published templates in the dashboard. This endpoint takes the template name + a list of phone numbers (max 999) and starts the campaign. Optionally provide a webhook_url to be notified when results are ready.

Body parameters

ParameterTypeRequiredDescription
request_idstringYesUnique request identifier.
template_namestringYesName of a published survey template.
senderstringYesActive sender number.
phone_numbersarrayYesPhone numbers — max 999.
webhook_urlstringNoURL to POST results to when the survey completes.

Response — 200 OK

{
  "success": true,
  "survey": {
    "id": 456,
    "status": "ready",
    "totalCount": 3
  }
}

Get survey result

GET /api/surveys/:id/result Per-number status + DTMF keys pressed.

Returns each recipient's status and the sequence of keys they pressed in response to the survey questions.

Response — Completed

{
  "success": true,
  "isComplete": true,
  "numbers": [
    {
      "number": "019XXXXXXXX",
      "status": "answered",
      "pressedKeys": ["1", "5"]
    }
  ]
}

Survey webhooks

If you provided a webhook_url when creating a survey, Protiddhoni will POST the final results to that URL when the survey completes.

POST body delivered to your webhook URL

{
  "survey_id": 456,
  "results": [
    {
      "phone_number": "019XXXXXXXX",
      "status": "answered",
      "responses": ["1", "5"]
    }
  ]
}

Your webhook endpoint should respond with 2xx to acknowledge. Make it idempotent — survey results may be re-delivered on transient errors.

Error responses

The API uses standard HTTP status codes. All error bodies share the shape {"success": false, "message": "..."} — branch on the status code and message.

StatusMeaningExample response
401Unauthorized — token missing or invalid{"success": false, "message": "Unauthorized"}
400Bad request — schema or duplicate input{"success": false, "message": "Duplicate phone number found"}
402Payment required — top up your balance{"success": false, "message": "Insufficient balance"}
403Forbidden — voice/sender not approved{"success": false, "message": "Voice not found or not approved"}
404Not found — broadcast/survey id doesn't exist{"success": false, "message": "Broadcast not found"}
500Internal server error — our fault, retry{"success": false, "message": "Failed to create OTP broadcast"}
